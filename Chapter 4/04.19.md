# Exercise 4.19
> Given that ptr points to an int, that vec is a vector<int>, and that ival is an int, explain the behavior of each of these expressions. Which, if any, are likely to be incorrect? Why? How might each be corrected?

- `ptr != 0 && *ptr++`
- `ival++ && ival`
- `vec[ival++] <= vec[ival]`

## Solution

- By looking at the expression `ptr != 0 && *ptr++`, we might assume that the author intended to check the pointer and increment the value it points to (i.e., `++*ptr`). However, the code is written incorrectly for that purpose. While the first subexpression (`ptr != 0`) is correct, the second is problematic. The postfix unary operator (`lvalue++`) has higher precedence than the dereference operator (`*`), meaning `*ptr++` is evaluated as `*(ptr++)`. The subexpression `*ptr++` dereferences an `rvalue` copy of the original `ptr`, and checks whether it is not equal to `0`, then increments the pointer itself. Since `ptr` now points past the single `int`, any subsequent dereference of `ptr` will result in undefined behavior. **Correction:** `ptr != 0 && ++*ptr`
- Due to the use of the logical AND operator (`&&`), the subexpression `ival++` must be completely executed before moving to the second subexpression (`ival`). The expression `ival++` compares a copy of the original `ival` to `0` and then increments `ival`. Only if the first subexpression yields true, is the second subexpression considered. The second expression uses the already incremented `ival`, and it is compared to `0` as well. The expression is correct, but may be misleading to the user. **Correction:** `ival && ival+1`
- Unlike the logical AND operator (`&&`), the less-than-or-equal operator (`<=`) does not provide short-circuit evaluation. In this case, incrementing `ival` (`ival++`) is not guaranteed to be evaluated before the expression `vec[ival]` which may lead to serious problems. **Correction:** `vec[ival] <= vec[ival+1]; ++ival;`
