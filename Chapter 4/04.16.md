# Exercise 4.16
> Although the following are legal, they probably do not behave as the programmer expects. Why? Rewrite the expressions as you think they should be.

- `if (p = getPtr() != 0)`
- `if (i = 1024)`

## Solution

- `if (p = getPtr() != 0)` - the assignment operator (`=`) has lower precedence than the inequality operator (`!=`). This means that the subexpression `getPtr() != 0` is evaluated first and its `bool` result is then assigned to `p`. To fix this use parentheses: `if ((p = getPtr()) != 0)`.
- `if (i = 1024)` - the expression `i = 1024` assigns the value 1024 to the variable `i`, and then the result (`1024`) is evaluated as a boolean condition. Since `1024` is non-zero, this condition always evaluates to `true`. The programmer likely intended to test for equality. Use the equality operator (`==`) instead: `if (i == 1024)`.
