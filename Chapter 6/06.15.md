# Exercise 6.15
> Explain the rationale for the type of each of find_char’s parameters In particular, why is s a reference to const but occurs is a plain reference? Why are these parameters references, but the char parameter c is not? What would happen if we made s a plain reference? What if we made occurs a reference to const?

## Solution

- **Why is `s` a reference to const?** <br>
  **(1)** A const reference may be bound to both const and non-const objects, making the function more flexible. **(2)** Larger types such as `string` or `vector`, should be passed by reference rather than by value to avoid unnecessary copying.
- **Why is `c` a plain character?** <br>
  **(1)** Small built-in types (e.g., `bool`, `short`, `int`) are cheap to copy, so passing them by value is efficient and avoids reference overhead. **(2)** Additionally, the function only reads `c` and does not need to modify the original argument. 
- **Why is `occurs` a plain reference?** <br>
  Because the function already returns a value (`string::size_type`), a reference parameter is used to return additional information to the caller. Since `occurs` is intended to be modified inside the function, it cannot be a reference to const.
- **What would happen if we made s a plain reference?** <br>
  We would not be albe to pass `const string` object, or string literals (e.g., `"Hello World"`).
- **What if we made occurs a reference to const?**
  The code would fail to compile because the function needs to update the value of `occurs`, which is forbidden for a const reference.
