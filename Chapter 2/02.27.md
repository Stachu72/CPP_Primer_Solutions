# Exercise 2.27
> Which of the following initializations are legal? Explain why.

(a) `int i = -1, &r = 0;` <br>
(b) `int *const p2 = &i2;` <br>
(c) `const int i = -1, &r = 0;` <br>
(d) `const int *const p3 = &i2;` <br>
(e) `const int *p1 = &i2;` <br>
(f) `const int &const r2;` <br>
(g) `const int i2 = i, &r = i;`

## Solution

(a) 
- `int i = -1` - The `signed int` type can hold negative numbers, `-1` fits in the `16-bits int`, 
- `int &r = 0` - invalid, `non-const` references could not be initialized with literals. 

(b)
- `int *const p2 = &i2`- If `i2` is of type `non-const int`, then this initialization is valid,

(c)
- `const int i = -1` - It is correct, but cannot be changed later,
- `&r = 0` - the complete type of `&r` is `const int &r`. The `const` references can be initialized with literals. The initialization is correct.

(d)
- `const int *const p3 = &i2` - Valid only if the variable `i2` is of int type.

(e) 
- `const int *p1 = &i2` - Same as above, `i2` should be of int type if we want it to be initialized correctly.

(f) 
- `const int &const r2` - The phrase `&const` is invalid; there is no such thing.

(g)
- `const int i2 = i` - The initialization is correct only if the variable `i` is of `int` type,
- `&r = i` - The full expression is `const int &r = i`, and, as above, `i` should be of `int` type.
